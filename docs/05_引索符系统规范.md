# agent-codebook 规范 v0.5

> **本文件是 `agent-codebook` 的核心规范（Normative）。**
> 定义一种把长内容改写为「代号 + 引索符」的方法：代号指向外置字典库，
> 改写后的常驻内容只保留符号串。
>
> **受众**：任何 agent 宿主、任何语言的实现者 —— 本规范不绑定具体平台。
>
> 状态：**v0.5** ｜ 参考实现见 [`../src/`](../src)，测试 43/43 通过

---

## 0. 文档约定

| 用语 | 含义 |
|:---|:---|
| **必须**（MUST） | 强制要求；不满足即不合规 |
| **禁止**（MUST NOT） | 强制禁止 |
| **应当**（SHOULD） | 强烈建议；偏离须说明理由 |

### 0.2 规范性 / 参考性

| 标记 | 含义 |
|:---|:---|
| **[规范]** | 强制；实现与校验以此为准 |
| **[参考]** | 解释、示例、理由；不构成要求 |

### 0.3 名词定义

| 术语 | 定义 |
|:---|:---|
| **概念单元**（unit） | 可被独立寻址的最小语义块（一条规则、一个结论、一个函数职责） |
| **代号**（code） | 标识概念单元的短字符串（如 `R1`） |
| **字典**（lexicon） | 代号 → 含义 / 保真度 / 详情路径 的映射表 |
| **引索符**（sigil） | 本规范定义的符号，用于组织代号、约束语义 |
| **符号串**（stream） | 由代号与引索符组成的压缩后文本 |
| **宿主**（host） | 承载 agent 的运行环境 |
| **可独立寻址** | 该单元可被**单独引用或替换**而不改变其余语义。**判据**：可赋予独立代号，且该代号单独出现时含义确定 |

## 1. 范围

### 1.1 本规范定义 [规范]

1. 抽象模型（概念单元 / 代号 / 字典 / 符号串）
2. 符号串的**语法**（EBNF）与**符号表**（20 符）
3. 代号命名规则与命名空间
4. 字典文件格式
5. 编码与展开过程
6. **一致性要求**与错误码（可机器校验）
7. 载体分离带来的**访问门控**性质、其前提与**宣称约束**（§2.3）

### 1.2 本规范不定义 [规范]

- 具体宿主的文件路径、目录结构、环境变量
- 具体宿主的能力约束（红线、调度机制、权限模型）
- 具体语言的词表（见 §11 语言包）
- 抽取阶段的实现细节（见 §10.1）

### 1.3 适用位置 [参考]

单轮上下文由五层构成：

| 层 | 内容 | 现状 |
|:--|:---|:---|
| ① System instructions | 角色 / 行为规则 | 稳定 |
| ② **注入式记忆 / 上下文** | 记忆纲要 · 项目约定 · 规则集 · 术语表 | **持续增长，缺通用方案** |
| ③ Conversation history | 对话轮次 · 工具结果 | 已有成熟压缩方案 |
| ④ Tool definitions | 工具 schema | 已有渐进披露方案 |
| ⑤ Retrieved content | RAG / 按需读取 | 非常驻 |

> **本规范作用于第 ② 层** —— 它是唯一「持续增长 × 长期驻留 × 尚无通用方案」的位置。
> 第 ③ ④ 层已有成熟方案，不在本规范范围内。

## 2. 抽象模型 [规范]

```
┌──────────────┐   编码   ┌──────────────┐
│  原始内容     │ ───────▶ │   符号串      │  ← 常驻（短）
│  (L1 全量)   │          │ 代号 + 引索符 │
└──────┬───────┘          └──────┬───────┘
       │                         │ 代号指向
       │ 存入                    ▼
       │                  ┌──────────────┐
       └─────────────────▶│   字典库      │  ← 外置（不占常驻额度）
          （详情）          │  代号 → 含义  │
                          └──────────────┘
```

### 2.1 三条不变量 [规范]

| # | 不变量 | 说明 |
|:--|:---|:---|
| `INV-1` | **字典与符号串分离** | 字典**禁止**内嵌于符号串所在的常驻内容中 |
| `INV-2` | **代号全局唯一且只增不改** | 同一代号在任何时刻只能有一个含义；历史代号不得改义 |
| `INV-3` | **每条字典项可解析到真实资源** | 详情路径必须存在（或明确标记为外部） |

> **可检测性**：三条不变量**必须**各有至少一条校验规则 ——
> `INV-1` → `V-09` ｜ `INV-2` → `V-04` ｜ `INV-3` → `V-03`。
> 无校验规则的不变量视为**未生效**。

> **INV-1 的理由（一 · 截断安全）**：字典与内容共用同一份额度时，二者互相挤压；
> 且若字典位于常驻内容尾部，宿主截断会先损失字典，导致全部代号失去定义。
>
> **INV-1 的理由（二 · 访问门控）**：分离还产生**载体分离**效果 ——
> 符号串单独不承载含义，**须持字典才能还原**。这是一项**真实**的性质，
> 但其强度与前提必须写清（见 §2.3）。

### 2.2 压缩来源 [参考]

> **压缩来自「把内容搬去外置字典」，不来自「代号比原词短」。**

推论（规范性要求见括注章节，本节只给理由）：

- 压缩单元取**整条概念单元**，而非单个词（规范性要求见 §7.2 `P-2`）
- 代号宜尽可能短，否则指针成本吃掉收益（§6.3）
- 存在**盈亏平衡点**；低于该点压缩为负（判据见 §10.3）

### 2.3 载体分离与访问门控 [规范]

符号串与字典**分离存放**（INV-1），产生一项真实性质：**没有字典，无法还原内容**。

这在密码学上属 **码本替换**（codebook substitution）—— 一类真实存在的方法。
但它与「现代加密」有本质差别，**宣称时必须写清前提**，否则不被采信。

> **本节性质**：`AC-1`~`AC-3` 是**要求**（[规范]）；`§2.3.2` 与 `§2.3.3` 是**对宣称的约束**（同样强制）；
> 其中对密码学概念的说明属**理由**，不单独构成要求。

#### 2.3.1 成立的前提（三条，缺一则门控失效）

| # | 前提 | 失效后果 |
|:--|:---|:---|
| `AC-1` | 字典**必须**与符号串**分离存放**（不同仓库 / 不同注入上下文） | 同处一地 → **门控为零** |
| `AC-2` | 字典**必须**受访问控制保护 | 字典含 `meaning` / `match` 列，**其本身即承载内容** → 字典泄露 = 全部泄露 |
| `AC-3` | 代号**不应**暴露时序 | 顺序编号（`R1` `R2`）可据编号推断概念新增顺序 |

> **`AC-2` 是最容易被忽略的一条**：字典不是"什么都不知道的索引" ——
> 它的 `meaning` 列是内容的压缩式转述，`match` 列甚至含源文本片段。
> 因此**要保住门控，就要保住字典**；字典本身是**密钥兼内容**。

#### 2.3.2 不提供的性质（**禁止**宣称）

| 不提供 | 说明 |
|:---|:---|
| 密钥 / 算法 / 密钥轮换 | 无密钥可管，也无轮换机制 |
| 完整性保护 | 能写字典者即可改义；`V-04` + `rev` 只能**检测**，不能**阻止** |
| 抗分析性 | 结构、数量、模态、关系仍可被观察；代号可被频率分析 |
| 隐藏元信息 | 条目数、模态（`-` `!`）、并列/关系结构、头部（含字典文件名）**均暴露** |

#### 2.3.3 表述规范

| 场合 | 表述 |
|:---|:---|
| **应当**（推荐） | 「**载体分离 · 需字典方可还原**」 |
| **可以**（中性） | 「字典作为**码本**；门控依赖**持有**（possession-based）」 |
| **禁止** | 「加密」「安全加密」「防泄露」—— 未达密码学强度，易被拆穿 |

> **一句话**：这是**「持有即可读」的访问门控**，不是密码学保证。
> 它确实让**独有性**成立（字典在你手里、代号只增不改），但**不是**加密。

## 3. 符号串语法 [规范]

### 3.1 EBNF

```ebnf
document    = header , NL , { NL } , body , EOF ;
header      = "#LX" , version , { SP , attribute } ;
version     = digit , { digit } ;
attribute   = key , "=" , value ;
key         = ( "dict" | "mods" | "ns" | "fid" ) ;
value       = 1 * ( printable-ascii-except-space ) ;

body        = { NL | unit , { NL } , ( "|" | ";;" ) , { NL } } ;   (* 终止符前允许换行，与 L-9 一致 *)
unit        = term , { relation , term } ;
term        = [ modality ] , atom , [ fidelity ] ;  (* 前导 relation 已删 → 强制 L-7 *)

atom        = reference | keyvalue | literal ;
reference   = ( "@" | "^" ) , code ;
keyvalue    = key2 , ":" , atom1 ;
key2        = lower , { lower | digit | "-" } ;     (* 须以小写字母起始 *)
atom1       = qliteral | literal ;

code        = upper , { upper | digit } ,
              { "-" , 1 * ( upper | digit ) } ;     (* 连字符后可接数字 *)
modality    = "!" | "-" | "+" | "~" | "?" ;
relation    = ">>" | "||" | ">" | "<" | "&" | "=" ;   (* 多字符项在前，强制最长匹配 *)
fidelity    = ".=" | ".~" | ".!" ;

literal     = 1 * safe-char ;                       (* 不得含空格 *)
safe-char   = ALPHA | DIGIT | "." | "_" | "~" | "-" | "/" ;
qliteral    = '"' , { any-except-quote-and-nl | escape } , '"' ;
escape      = "\" , ( '"' | "\\" ) ;    (* 仅 \" 与 \\，与 §3.4 一致 *)
```

### 3.2 词法要求 [规范]

| # | 要求 |
|:--|:---|
| L-1 | **符号串**（§3.1 `document`）**必须**为纯 ASCII（U+0000–U+007F），除转义序列与**界定字面量内部**内容；**字典与语言包不受此约束**（见 §5.1） |
| L-2 | 换行**必须**为 `LF` 或 `CRLF`；实现**应当**接受二者 |
| L-3 | `code` **必须**以大写字母起始 |
| L-4 | 遇多字符符号时，词法分析**必须**最长匹配（`>>` 优先于 `>`；`||` 优先于 `|`） |
| L-5 | 转义符为 `\`（见 §3.4） |
| L-6 | **裸字面量**（`literal`）**禁止**含空格与引索符；需要时**必须**用界定字面量 `"..."` |
| L-7 | **关系符禁止连写** —— 每个关系符两侧**必须**各有原子（`@R1>@R2` 合法；`@R1>&@R2` 非法） |
| L-8 | 键名（`key2`）**必须**以小写字母起始（用于与数字 / 路径类字面量消歧） |
| L-9 | 正文**可以**跨行；空白行**必须**被忽略 |

### 3.3 头部 [规范]

格式：`#LX<version> <attr> <attr> ...`

| 属性 | 必填 | 取值 | 说明 |
|:---|:---|:---|:---|
| `dict` | **是** | 路径或 URI | 字典位置（**只声明一次**，禁止逐条重复） |
| `mods` | 否 | 模态符集合 | 本文件**实际使用**的模态符 |
| `ns` | 否 | 命名空间声明 | 若使用类别前缀（**定义见 §6.2**）**则必须**声明 |
| `fid` | 否 | `yes` | 声明本文件含保真度后缀 |

**要求**：

- 头部**必须**位于文档首行
- 头部**禁止**超过 120 字符（它是固定开销，须保持极小）
- `dict` 与 `detail_path` 为**相对路径**时，**必须**相对于**声明或记录它的文件所在目录**解析；绝对路径与 URI 除外
- 未在 `mods` 中声明的模态符**禁止**在正文出现（校验规则 V-06）

### 3.4 字面量与转义 [规范]

字面量分两种，选择规则如下：

| 情况 | 写法 | 示例 |
|:---|:---|:---|
| 仅含**安全字符**（字母 / 数字 / `.` / `_` / `~` / `-` / `/`） | 裸字面量 | `stop-start`、`mem/rules/rl.md` |
| 含**空格**或**引索符** | **必须**界定：`"..."` | `"force stop"`、`"stop+start"` |

**转义**（仅用于界定字面量内部）：

| 场景 | 写法 |
|:---|:---|
| 字面量内需出现 `"` | 写作 `\"` |
| 字面量内需出现 `\` | 写作 `\\` |
| 行尾续行 | 禁止（无续行语法） |

> **为什么这样分**：裸字面量有限字符集后，**常见路径 / 标识符无需任何转义**；
> 只有真正含空格或符号的文本才付出界定成本。

### 3.5 消歧规则 [规范]

词法分析遇歧义时**必须**按以下顺序判定：

| # | 情形 | 判定 |
|:--|:---|:---|
| D-1 | 原子以小写字母起始，且本行内有 `:` | 判为**键值**（`key2`） |
| D-2 | 原子以数字开头 | 判为**字面量**（不可能是键值） |
| D-3 | 原子以 `"` 起始 | 判为**界定字面量** |
| D-4 | 原子以 `@` / `^` 起始 | 判为**引用** |
| D-5 | 其他 | 判为**裸字面量** |

> **D-1 / D-2 的理由**：`127.0.0.1:5432` 若干位为数字，它**不是**键值；
> 限制键名以小写字母起始，即可与「数字开头 + 含冒号」的字面量彻底分开。
>
> **写法提示**：`:` **不在** `safe-char`（§3.1），故 `127.0.0.1:5432` 这类含冒号的
> 非键值文本**必须**写作**界定字面量** `"127.0.0.1:5432"`（§3.4），裸写无合法形式。

## 4. 符号表 [规范]

**共 20 符，6 组。**

### 4.1 组 A · 结构（4）

| 符 | 名称 | 语义 | 示例 | 语法归属 |
|:--|:---|:---|:---|:---|
| `\|` | 并列 | 同级项分隔 | `@R1\|@R2` | 分隔符（非关系） |
| `:` | 键值 | 键与值绑定 | `state:active` | 键值（非关系） |
| `;;` | 终止 | 一个语义单元结束 | `... ;;` | 终止符 |
| `>>` | 从属 | 后项从属于前项 | `@M1>>@F1` | ⚠️ 语法上归入 `relation` |

> ⚠️ **`>>` 的语法归属**：它在语义上属「结构」（从属），但**语法上必须**由 `relation` 产生式承载 ——
> 否则无产生式引用它，`@M1>>@F1` 无法解析。
> 因此 `relation` 共 6 项：`>>` `||` `>` `<` `&` `=`。

### 4.2 组 B · 引用（2）

| 符 | 名称 | 语义 |
|:--|:---|:---|
| `@` | **必展开引用** | 使用方**必须**查字典才能理解 |
| `^` | **复用引用** | 指向上文已展开的同一代号 |

**示例**：

```
^F1>@F3         复用 F1（不重复展开），并声明它导致 F3
@R1|^R1         两个并列项，后一个复用前一个
```

> **规则**：符号串中所有代号**必须**带引用符。裸代号**禁止**出现。
> **理由**：短代号（2–4 字符）与正文极易撞车（`R1` 可能是型号、`F2` 可能是按键）。
> 加引用符后歧义双向消除：正文里的 `R1` 不会被误认为引用，符号串里的 `@R1` 不会被误认为正文。

### 4.3 组 C · 模态（5）

| 符 | 名称 | 语义 |
|:--|:---|:---|
| `!` | 必须 | 强制要求 |
| `-` | 禁止 | 强制禁止 |
| `+` | 应当 | 建议，可偏离需说明 |
| `~` | 允许 | 可选 |
| `?` | 待确认 | 未验证 / 待定 |

> **为什么必须有模态组**：模态（限界、强制、许可）**承载真值**。
> 例：「**仅**支持 3 种格式」中的「仅」若被删去，语义从"排他"变为"至少"，
> 这是**事实错误**而非"精简"。纯删减类方法没有表达模态的位置，必然丢失该信息。

### 4.4 组 D · 关系（5）

| 符 | 名称 | 语义 | 备注 |
|:--|:---|:---|:---|
| `>` | 导致 | 前项导致后项 | |
| `<` | 依赖 | 前项依赖后项 | |
| `&` | 且 | 合取 | |
| `\|\|` | 或 | 析取 | 双符；见下 |
| `=` | 等价 | 定义 / 即 | |

> ⚠️ **「或」不得使用单 `\|`** —— 单 `\|` 已是组 A 的并列分隔符。
>
> ⚠️ **`/` 不得作为关系符** —— 它是文件路径与 URL 的通用分隔符，
> 在 agent 上下文中出现频率极高。若把 `/` 定为「或」，则 `mem/rules/rl.md`、
> `path:/api/items` 等**全部无法裸写**。
>
> → **`/` 已归还字面量字符集**（§3.1 `safe-char`）。
>
> **最长匹配要求**：`\|\|` 优先于 `\|`（L-4）。

### 4.5 组 E · 保真度（3）

| 后缀 | 名称 | 定义 | 可用性 |
|:---|:---|:---|:---|
| `.=` | 严格等价 | 与原文字面一致（如纯去重、模板化） | 可直接当原文使用 |
| `.~` | 语义等价 | 信息要素全保留，措辞有变 | 可作判断依据 |
| `.!` | **有损** | 丢失了某类信息 | **禁止**作为最终依据 |

> **要求**：标 `.!` 的条目**必须**在字典的 `loss` 列注明丢失类别（§5.2）。
> **要求**：任何**最终结论或取证**，实现**必须**回读原始内容，**禁止**仅凭 `.!` 项下结论。

> **同符号双语义核对**（已消解）：
> - `\|` 仅作并列分隔符（「或」改用 `\|\|`，靠最长匹配区分）
> - `?` 仅作模态（早期草案曾兼任「待解析」引用，已删）
> - `/` **不在符号表内**，属字面量字符

## 5. 字典规范 [规范]

### 5.1 格式：TSV

**必须**为制表符分隔的文本文件，**UTF-8 编码**，首行为**列名行**。

> **作用域说明**：字典与语言包**不受** L-1 的 ASCII 约束 ——
> 它们**应当**使用母语文字，以利人类审阅（§5.2 `term` 列的用意即在此）。

**列名行**（**禁止**任何前缀符号；列名即字面列名）：

```
code	term	meaning	fidelity	detail_path	match	loss
```

**数据行示例**（下列制表符以 `→` 示意）：

```
R1→红线1→不可逆操作必须走优雅停止→.~→docs/rules/rl.md→禁止强制终止→
F1→成绩计算→按权重求和后排名→.=→src/scoring.md→计算成绩→
S1→题库为空→item 表 0 行→.!→docs/issues.md→item=0→细节
```

### 5.1.1 字段转义 [规范]

Tab 既是分隔符，字段内**禁止**出现裸 Tab 或裸换行。转义约定：

| 字符 | 写法 |
|:---|:---|
| 制表符 | `\t` |
| 换行 | `\n` |
| 回退符 | `\r` |
| 反斜杠 | `\\` |
| 分号（**仅** `match` 列，用作别名分隔） | `\;` |

**要求**：

- 除 `match` 列的别名分隔符 `;` 外，字段内**禁止**出现裸 `Tab` / `LF` / `CR`
- 解析**必须**先按 Tab 切列，**再**对每个字段做转义还原（顺序不可颠倒）
- 违反者报 `LX-E009`

### 5.2 列定义

| 列 | 必填 | 类型 | 说明 |
|:---|:---|:---|:---|
| `code` | **是** | 代号（语法 §3.1 `code` 产生式；命名 §6） | 全局唯一；**只增不改** |
| `term` | **是** | 文本 | **原名**。短代号不可读，此列是人类审阅与回查的唯一入口 |
| `meaning` | **是** | 文本 | 一句话含义（多数场景读到这层即足够） |
| `fidelity` | **是** | `.=` / `.~` / `.!` | 该条信息能信到什么程度 |
| `detail_path` | **是** | 路径或 URI | 详情位置；**必须**可解析（V-03） |
| `match` | 否 | 文本，`;` 分隔 | 供编码器匹配源文本的别名集 |
| `loss` | 条件必填 | 文本 | `fidelity=.!` 时**必须**填写（丢失类别，见 §5.3） |
| `rev` | 否 | 短哈希 | **含义指纹**。用于 V-04 检测「代号语义被改」。无此列时，`INV-2` **必须**由版本控制保证 |

> **没有 `term` 列的后果**：字典退化为 `R1=?` 的天书，人类无法审阅 —— 直接违背后果见 §6。

### 5.3 丢失类别（`loss` 列取值） [规范]

| 取值 | 丢失内容 |
|:---|:---|
| `修饰` | 程度 / 语气 / 情感色彩 |
| `举例` | 说明性例子 |
| `推导` | 中间推理步骤 |
| `细节` | 实现 / 参数细节 |
| `样式` | 格式 / 排版 |

## 6. 代号命名规范 [规范]

### 6.1 语法

语法见 **§3.1 `code` 产生式**（**唯一来源**；本节不重复定义，避免两处宽严不一）。

**合法**：`R1` `F12` `S1` `M1` `RL-3` `AUTH-VERIFY`
**非法**：`r1`（小写起始）`R-`（尾部连字符）`R1A-`（同）`_R1`（下划线）

### 6.2 命名空间

使用类别前缀时**必须**在头部用 `ns` 声明。推荐前缀：

| 前缀 | 类别 |
|:---|:---|
| `R` | 规则（Rule） |
| `S` | 状态（State） |
| `F` | 功能（Function） |
| `D` | 数据（Data） |
| `M` | 模块（Module） |

**不要求**使用前缀。若采用全局纯序号（`C1`、`C2`…），**可以**省略 `ns`。

### 6.3 长度

- 代号长度**应当**为 2–4 字符
- 代号长度**应当**不超过 24 字符；超出即**应当**检视命名粒度（SHOULD，不设错误码）

## 7. 编码过程 [规范]

### 7.1 步骤

| 步 | 动作 | 完成判据 |
|:--|:---|:---|
| 1 | **划分概念单元** | 每单元**可独立寻址**（定义见 §0.3）；**禁止**单词切分（P-2） |
| 2 | **查重** | 该单元是否已有代号（大小写敏感）？有则复用，**禁止**新建 |
| 3 | **评估收益** | 通过 §10.3 判据；未通过则**不编码** |
| 4 | **分配代号** | 符合 §6；仅在无可用旧代号时新建 |
| 5 | **写入字典** | 必备列齐备（§5.2）；列数须与列名行一致（§5.1） |
| 6 | **改写内容** | 用 `@code` + 模态 / 关系 / 保真符组织 |
| 7 | **生成头部** | 声明 `dict`；正文含模态符**必须**声明 `mods`，用类别前缀**必须**声明 `ns`（§3.3）；含保真度后缀**应当**声明 `fid` |
| 8 | **校验** | 通过 §8.2 全部校验规则（最小集见 §8.3） |

### 7.2 禁止事项

| # | 禁止 |
|:--|:---|
| P-1 | 字典内嵌于常驻内容（违 INV-1） |
| P-2 | 以**单词**为压缩单元 |
| P-3 | 裸代号出现于符号串 |
| P-4 | 改写后丢弃模态（`!` `-` `+` `~` `?`） |
| P-5 | 对 `.!` 项下最终结论 |
| P-6 | 修改既有代号的语义（违 INV-2） |
| P-7 | 提交**未经 §9 展开验证**的符号串（违 V-10） |

## 8. 一致性要求 [规范]

### 8.1 错误码

| 码 | 级别 | 条件 |
|:---|:---|:---|
| `LX-E001` | 错误 | 缺少头部或头部格式非法 |
| `LX-E002` | 错误 | 使用了字典中不存在的代号（悬空引用） |
| `LX-E003` | 错误 | 字典 `detail_path` 不可达 |
| `LX-E004` | 错误 | 代号重复定义 |
| `LX-E005` | 错误 | **符号串内**出现非 ASCII（界定字面量内除外）或未转义的引索符 |
| `LX-E006` | 错误 | 使用了未在 `mods` 声明的模态符 |
| `LX-E007` | 错误 | `fidelity=.!` 但 `loss` 列缺失 |
| `LX-E008` | 错误 | 裸代号出现于符号串 |
| `LX-E009` | 错误 | 字典字段含裸 Tab / 换行（未按 §5.1.1 转义） |
| `LX-E010` | 错误 | 字典列数与列名行不符 |
| `LX-E011` | 错误 | `^code` 缺少先行 `@code`（复用了一个从未展开的代号） |
| `LX-E012` | 错误 | 头部版本号不受支持（实现无法按该版本解析） |
| `LX-E013` | 错误 | 字典与符号串位于**同一常驻文件**（违 INV-1 / `V-09`） |
| `LX-E014` | 错误 | 同一代号的 `rev` 发生变化，疑似语义被改（违 INV-2 / `V-04`） |
| `LX-W001` | 警告 | 头部声明了未使用的符号 |
| `LX-W002` | 警告 | 字典中存在从未被引用的代号（死词） |
| `LX-W003` | 警告 | 内容长度低于盈亏平衡点，压缩为负 |
| `LX-W004` | 警告 | `term` 列**存在但某行值为空**（缺**列**属必填列缺失，报 `LX-E010`，§5.2） |
| `LX-W005` | 警告 | 头部 `fid` 声明与正文保真度后缀的实际使用不一致 |

### 8.2 校验规则

| # | 规则 | 依据 |
|:--|:---|:---|
| V-01 | 头部存在且 ≤ 120 字符，含 `dict` | §3.3 |
| V-02 | 所有 `@` / `^` 引用的代号在字典中有定义 | INV-3 |
| V-03 | 所有 `detail_path` 可达（或标为外部 URI） | INV-3 |
| V-04 | 代号无重复定义；**若字典含 `rev` 列**，比对历史 `rev` 检测语义变更（无 `rev` 时依赖版本控制，见 §5.2） | INV-2 |
| V-05 | **符号串**为纯 ASCII；未转义引索符数为零 | L-1 |
| V-06 | 正文出现的模态符 ⊆ 头部 `mods` | §3.3 |
| V-07 | 每条 `.!` 项在字典有 `loss` | §5.3 |
| V-08 | 无裸代号 | §4.2 |
| V-09 | 字典与符号串**不在同一常驻文件** | INV-1 |
| V-10 | **编码结果可展开**：对符号串执行 §9.1 全部步骤，须通过 §9.2 成功判据 | §9.2 |
| V-11 | 每个 `^code` **必须**存在先行 `@code`（先展开、后复用） | §4.2 |
| V-13 | 头部版本号 ≤ 实现支持版本且语义兼容（§13 `E-3`） | §13 |

> **编号说明**：`V-12` 已**撤销**（原为「`fid` 声明一致性」，因其与 `LX-W005` 严重级冲突而删除）。
> 按编号**不复用**原则，`V-12` 空位保留，**禁止**再分配给其他规则。

### 8.3 最小可用校验集

实现**至少必须**支持 `V-01` `V-02` `V-08` `V-09` ——
这四条覆盖最严重的失效：无法解析字典、代号无定义、歧义、字典被一同截断。

### 8.4 语法层与语义层的职责分离 [规范]

**这两层不能互相代替**。实现**必须**两者都做。

| 层 | 检查内容 | 能否在此层强制 |
|:---|:---|:---|
| **语法层** | 头部格式、词法、符号串结构、转义、消歧 | 能 |
| **语义层** | 代号是否已定义、`dict` 是否可读、路径是否可达 | **不能** —— 需外部信息 |

**以下项在语法层无法拦截，必须由语义层负责**：

| 项 | 为何语法层拦不住 | 负责规则 |
|:---|:---|:---|
| 裸代号出现 | 字面量本就是合法原子（无法仅凭形状判定） | `V-08` |
| 头部缺少 `dict` | 头部语法上是合法的键值集合 | `V-01` |
| 代号未在字典定义 | 需读字典才能知 | `V-02` |
| 详情路径不可达 | 需访问文件系统 | `V-03` |
| 模态符未声明 | 需对照头部 | `V-06` |

> **强制要求**：实现**禁止**仅凭语法通过就判定"内容合规"。
> **理由**：语法通过的文档仍可能引用不存在的代号 —— 这正是"看起来对"的典型形态。

## 9. 展开（解码）过程 [规范]

> **与 §8 的关系**：§9 是**行为规范**，§8.2 `V-10` 是**它的校验入口**。
> 实现**必须**两者都做 —— 只做 §9 不校验，等于没有保证。
>
> **引用方向**：只允许 §8 → §9（`V-10` 引用本节判据）。
> 本节**禁止**反向引用 `V-10`，否则会构成循环依赖（§9.2 ← V-10 ← §9.2）。
> `^` 的先行性由 §8.2 `V-11` 独立校验，不属于本节判据。

### 9.1 步骤与完成判据

| 步 | 动作 | 完成判据 | 失败时 |
|:--|:---|:---|:---|
| 1 | 读头部，定位字典 | 头部合法且 `dict` 可读 | `LX-E001` / `LX-E003` |
| 2 | 按 §3 词法分析符号串 | 无词法错误 | `LX-E005` |
| 3 | 对每个 `@code` 查字典 | 每个代号都取到 `meaning` | `LX-E002` |
| 4 | 对 `^code` 复用上文含义 | 该代号在上文已展开（**存在先行 `@code`**） | `LX-E011` |
| 5 | 遇 `fidelity=.!` 时标注 | 已产出「不可作最终依据」提示 | `LX-E007` |
| 6 | 按需读 `detail_path` | **二选一**：① 读且路径可达（或为外部 URI）；② **未读**时**必须**标注「可达性未判定」 | `LX-E003` |

### 9.2 成功判据 [规范]

展开**视为成功**，当且仅当：

```
(1) 所有步骤完成，且
(2) 无任何 LX-E* 级错误，且
(3) 每个 @ 引用都被解析为具体含义（无跳过、无占位）
```

> **「所有步骤完成」的口径**：步6（按需读）的「完成」**不等于**「必须读过」——
> 未读时**可以**判定成功，但**必须**在结果中**显式标注**「`detail_path` 可达性未判定」。
> **禁止**在未读且未标注的情况下视为完成（否则违 §9.3 的禁止静默降级精神）。

### 9.3 禁止静默降级 [规范]

| # | 禁止 |
|:--|:---|
| ND-1 | 字典不可读时返回空结果（**必须**报 `LX-E003`） |
| ND-2 | 遇到未定义代号时跳过（**必须**报 `LX-E002`） |
| ND-3 | 用代号本身充作含义（**必须**报错，**禁止**原样输出 `@R1`） |
| ND-4 | 对 `fidelity=.!` 项不提示就当作完整信息使用 |

> **理由**：这四条都会产生「看起来成功」的假象 —— 输出非空、无异常，
> 但内容是错的。属最危险的失效形态。

## 10. 可用性判据 [规范]

### 10.1 抽取阶段

本规范**不规定**抽取算法（可用规则、词频、模型辅助或人工）。
但抽取结果**必须**满足 §7 全部要求。

### 10.2 无损往返（日志 / 结构化数据）

若原文可模板化，实现**应当**保证：

```
∀ 行 i : render(template_i, fields_i) == line_i
```

不满足的行**禁止**模板化，须保留原文并计入报告。

> **报告**（report）**至少**应含三项：源行号、未模板化原因、原文片段。
> 缺任一项即无法审计该行，视为报告不合规。

### 10.3 盈亏平衡判据

压缩**必须**满足：

```
len(stream) + len(header) < len(original)
```

**否则禁止编码**，并报 `LX-W003`。

> 固定开销（头部）意味着存在盈亏平衡点；其**具体值随语言与内容而变**，
> 实现**应当**提供测量方法而非硬编码阈值。

## 11. 语言包 [规范]

模态语义是**语言无关**的；但**识别模态的词汇**是语言相关的。

**要求**：语言相关的词表**必须**置于独立的**语言包**中，**禁止**写入本规范正文。

### 11.1 文件

| 语言包 | 内容 |
|:---|:---|
| `<lang>.modality.tsv` | 该语言中承载模态的词 / 短语 → 对应模态符 |
| `<lang>.stopwords.tsv` | 可安全删除的填充词（须标注不改变真值） |

`<lang>` **必须**为 BCP 47 语言标签（如 `zh`、`en`、`zh-Hans`）。

### 11.2 格式

两个包**均为 TSV**，格式与 §5.1 一致（含 §5.1.1 转义规则）。

**`<lang>.modality.tsv`**

```
term	modality	note
仅	!	表排他；删去会改变真值
至少	+	下限
不得	-	禁止
可能	?	不确定
```

| 列 | 必填 | 说明 |
|:---|:---|:---|
| `term` | **是** | 承载模态的词或短语 |
| `modality` | **是** | **必须**取自 §4.3 的模态符集合（`!` `-` `+` `~` `?`） |
| `note` | 否 | 说明（**应当**写明「删去是否改变真值」） |

**`<lang>.stopwords.tsv`**

```
term	note
值得注意的是	框架词，删后结论不变
```

| 列 | 必填 | 说明 |
|:---|:---|:---|
| `term` | **是** | 可安全删除的填充词 |
| `note` | 否 | **应当**说明为何视为不改变真值 |

### 11.3 约束 [规范]

| # | 约束 |
|:--|:---|
| G-1 | 语言包**禁止**包含任何**承载真值**的词（限界词、量词、否定） |
| G-2 | `modality` 列取值**必须** ⊆ §4.3 模态符集合 |
| G-3 | 同一个 `term` **禁止**同时出现在 `modality` 与 `stopwords` 两包 |
| G-4 | `stopwords` 中的词**必须**可被删除而不改变句子的真值 |

> **G-4 的检验方法**：删除该词后，若句子由「事实」变为「错误」或「另一事实」，
> 则它**不属** stopword，**必须**移入 `modality` 或不收录。

## 12. 跨宿主适配 [规范]

实现**必须**按以下依赖层级组织，**L0 必须能独立成立**：

| 层 | 依赖 | 内容 |
|:---|:---|:---|
| **L0 零依赖** | 无 | 纯规范文本 + 普通文件。宿主只需能读写文件 |
| **L1 文件约定** | L0 | 符号串与字典作为普通文件处理 |
| **L2 工具协议** | L0 | 提供 MCP server 等标准工具接口（可选） |
| **L3 原生集成** | L0 | 特定宿主的 hook / plugin（可选） |

> L2 / L3 **禁止**作为 L0 或 L1 生效的前置条件 —— 它们是**便利层**，不是门槛
> （与「L0 必须能独立成立」互为保障）。

**铁律**：L2 / L3 **禁止**成为使用前提。任何声称支持本规范但要求特定宿主的实现，**不合规**。

## 13. 版本与演进 [规范]

| # | 规则 |
|:--|:---|
| E-1 | 符号**只增不改**；语义变更**必须**升主版本号 |
| E-2 | 新增符号**必须**为旧实现可忽略（向后兼容）或升主版本号 |

| 项目 / 工作 | 它做什么 | 与本规范的关系 |
|:---|:---|:---|
| `LLMLingua` 系 | token 级剪枝（有损） | 不同层：剪枝不改变表示法 |
| `CompactPrompt` | LZW 式 n-gram 缩写 | 同源思想；未定义结构化语法 |
| arXiv:2604.13066 | 字典编码 + 上下文内学习 | 同源思想；字典置于 prompt 内部 |
| `claw-compactor` | 多阶段删减 + 纯编号替换 | 同目标；编号无语义、无语法 |
| `context-compress` | 压成索引行 | 同目标；无代号编码 |
| `mcp-compressor` | 工具描述渐进披露 | 不同层（④ 工具面） |
| arXiv:2607.08032 | 多保真度（P-fid）的形式化 | 保真度概念的学术形式化早于本规范 |

> **本规范的主张**：**代号编码 + 引索符语法 + 外置字典 + 机器可校验**这个组合。
> **不主张**：「发明了字典压缩」—— 缩写字典、无损可逆、多保真度均有先例。

## 15. 已知限制 [参考]

| # | 限制 | 说明 |
|:--|:---|:---|
| 1 | **短内容膨胀** | 头部为固定开销；低于盈亏平衡点（§10.3）时压缩为负。**小内容不应使用** |
| 2 | **收益随内容而异** | 已高度精简的内容收益接近零 |
| 3 | **抽取质量有上限** | 纯规则抽取弱于人工；模型辅助有成本且结果不确定 |
| 4 | **需学一次** | 使用方须先读规范；此后可长期复用 |
| 5 | **无跨语料基准** | 目前数据来自单一实现与有限样本，**未做独立基准** |
| 6 | **非首创** | 见 §14 |

## 16. 最小示例 [参考]

### 16.1 输入（3 条规则，118 字符）

```
红线1：不可逆操作必须走优雅停止流程，禁止使用强制终止进程的方式跳过收尾清点步骤。
红线2：禁止同时运行多个实例进程，否则端口冲突会触发系统的保护性自动停用机制。
红线3：重启必须使用统一的命令入口，禁止以先停后起叠加的两次独立操作来替代。
```

### 16.2 符号串（45 字符）

```
#LX1 dict=lexicon.tsv mods=-!
-@R1|-@R2|-@R3
;;
```

**⚠️ `ns` 义务**：`R` 属**类别前缀**（§6.2），故**正式使用**本示例的代号时，
头部**必须**声明 `ns`（§3.3）。合规写法（在 §16.2 基础上补 `ns`）：

```
#LX1 dict=lexicon.tsv mods=-! ns=R
-@R1|-@R2|-@R3
;;
```

本节示例为保持「最小」未含 `ns`，仅演示**语法**；
若不想承担 `ns` 义务，改用**全局纯序号**（`C1` `C2` `C3`）即可按 §6.2 省略。

### 16.3 字典（外置）

```
code	term	meaning	fidelity	detail_path	match	loss
R1	红线1	不可逆操作必须走优雅停止流程，禁止强制终止进程	.~	docs/rules.md	禁止强制终止	
R2	红线2	禁止同时运行多个实例，端口冲突会触发保护性停用	.~	docs/rules.md	禁止同时运行	
R3	红线3	重启必须使用统一的命令入口，禁止先停后起叠加	.~	docs/rules.md	禁止先停后起	
```

### 16.4 结果

| 项 | 值 |
|:---|:---|
| 原文 | 118 字符（不含换行） |
| 符号串 | 45 字符（含 29 字符头部） |
| 比值 | **2.62 : 1**（省 62%） |
| 去除头部后正文 | 14 字符（省 88%） |

> **对比**：同一内容若以**单词**为单位替换，则因头部开销而**膨胀**。
> 这印证 §2.2：压缩单元必须是整条概念单元。
