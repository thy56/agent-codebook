# 01 · 设计思路

> 本文回答三个问题：**为什么要做？为什么这么做？代价是什么？**

---

## 一、出发点：Agent 记忆的三个硬约束

### 约束 1 · 注入额度是硬上限，且**静默截断**

Agent 的启动文件（system prompt 常驻段）有字符上限。超限时**不报错**，而是**从尾部截断**。

> 实测背景（本仓）：单文件上限 **20,000 字符**、合计 **60,000 字符**；
> 超限行为是**静默截断**（不警告、不失败）。

**这个特性决定了本方案的形态** —— 后面所有设计选择，根子都在这一条。

### 约束 2 · 截断方向是"从尾部切"，不是"切最不重要的"

理想截断应保留最重要内容。实际是**物理位置决定生死**：排越后，越先被切。

### 约束 3 · 长概念反复占用额度

长期运行的 agent 会积累大量**反复出现**的长概念：规则组、项目名、术语、踩坑结论。
它们在多个条目里被**重复展开**，每次都吃掉完整字符数。

---

## 二、核心设计决策

### 决策 1 · 用"稳定短代号"替换 → 无损可逆

| 选项 | 取舍 | 选定 |
|:---|:---|:---|
| A. 摘要压缩（有损） | 省最多，但**会丢信息**，且不可逆 | ✗ |
| B. 删减内容（有损） | 直接丢知识 | ✗ |
| C. **代号替换（无损可逆）** | 省得少些，但**信息零丢失** | ✅ |

**理由**：Agent 记忆**不能有损** —— 丢掉的一条规则，可能正是下次踩坑的原因。
选择 C：牺牲压缩率，换**保真**。

### 决策 2 · ★ 字典**移到正文外**（本方案核心）

这是最关键的一步。考虑过三种摆放：

| 方案 | 表现 | 问题 |
|:---|:---|:---|
| A. 字典**内嵌正文**（开头） | 能展开 | 占 16% 额度**挤压正文**；且仍可能被截断 |
| B. 字典**内嵌正文**（结尾） | — | 🔴 **最先被截断 → 代号全变天书**（实测踩过） |
| C. **字典外置 + 正文留索引** | 索引极短（262 字符） | ✅ **选定** |

**C 的两个决定性好处**：

1. **不受截断影响** —— 正文里只有"词名索引"，最坏情况是索引被切；而**字典文件本身完整独立**，随时可查
2. **破掉零和关系** —— 内嵌时「字典越大 → 正文越少」；外置后**字典增长不再挤压正文**

> ⚠️ 注意：**光"代号替换"是不够的**。若字典内嵌，只是把"展开的内容"挪个位置，总量没省，还新增了截断风险。
> **真正解决约束 1/2 的是"外置"这一步。**

### 决策 3 · 代号**人可读**，不用机器码

| 选项 | 选定 |
|:---|:---|
| `<M1>` / `ABC1` 机器码 | ✗ |
| **`SILENT-FAIL` / `RL-3` 语义码** | ✅ |

**理由**：双重受众 ——
- **LLM**：语义码自带线索，即使字典暂时没读到也能**猜个大概**（比纯机器码更能兜底）
- **人类**：直接读正文时，`SILENT-FAIL` 比 `<M1>` 可读得多

### 决策 4 · 字典条目**必须带可解析路径**

```
代号 ｜ 含义 ｜ 详情位置
SILENT-FAIL ｜ 静默失效防治（六条原则…） ｜ memory/procedural/总规范/主规范/M-05_静默失效防治规范.md
```

**理由**：**没有路径的字典 = 另一种天书**。
代号 → 含义只解决"看懂"，代号 → 路径才解决**"取证"**（要细节时去哪读）。

**配套强制校验**：字典每条路径必须**真实存在**（否则条目等于失效）——这是可机器检查的。

### 决策 5 · 词典与"被压缩内容"**分离成两个生命周期**

| 文件 | 变化频率 | 注入方式 |
|:---|:---|:---|
| 正文（含索引） | 频繁增改 | **每轮常驻** |
| 字典文件 | 加词时改 | **按需读取** |

**理由**：**变化频率不同 → 不该共用同一份注入预算**。
字典改一次就常驻一次的成本，被彻底消除。

## 三、为什么这个方案"省"得过朴素做法

**朴素做法**：把长概念写短（比如"静默失效防治规范"→"静默规范"）
**问题**：① 语义模糊 ② 改名后正文全废 ③ 没有"取证入口"

**本方案**：`SILENT-FAIL` ① 语义清晰 ② 代号**只增不改**（历史正文永远可读）③ 字典给路径

**省的位置也不同** —— 朴素做法省"字"，本方案省**"额度"**：
- 省字 = 一次性的、同比例的（1000 字省 200 字）
- 省额度 = **结构性的**（字典不再常驻，收益随字典增大而增大）

## 四、与相邻方案的边界（不重复造轮子）

| 相邻方案 | 它解决什么 | 本方案的差别 |
|:---|:---|:---|
| **LLMLingua** 类（token 剪枝） | 让长文档进得去 | **有损**；且要额外模型；我们**无损 + 零依赖** |
| **Gisting**（软 token） | 极致压缩 | 需**微调**；不可读；我们**纯文本约定** |
| **CompactPrompt / Dict-Encoding**（n-gram 缩写） | 附件文档 / 日志 | 字典**在文档内或 system prompt 内**；我们**在正文外、惰性加载** |
| **RAG / 检索** | 按需取知识 | 我们不替代检索 —— **管的是"常驻记忆"** |
| **摘要 / 压缩记录** | 降 token | 有损；我们是**无损映射** |

**一句话定位**：
> 本方案**不是**要打赢"最大的压缩率"，而是要在
> **"常驻注入 + 硬上限 + 静默截断"** 这个特定战场上，做**无损且失效安全**的压缩。

## 五、代价与取舍（诚实清单）

| # | 代价 | 为什么可接受 |
|:--|:---|:---|
| 1 | 读正文时多一次"查表" | 索引已给词名，**仅需详情时才跳** |
| 2 | 压缩率**不如有损方案** | 记忆场景**保真 > 压缩率** |
| 3 | 需要**人工/agent 维护字典** | 有强制校验（查重 + 可达性）兜底 |
| 4 | 代号有**学习成本** | 会写进索引 + 字典，文档内自解释 |
| 5 | 替换收益取决于**重复频次** | 只对**高频长概念**编码；低频不编 |

## 六、设计原则（可直接照抄的 7 条）

```
P1  无损优先      —— 记忆场景不牺牲信息
P2  外置优先      —— 解释性内容不进常驻正文
P3  索引极短      —— 正文只留词名（目标 ≤ 300 字符）
P4  代号稳定可读  —— 语义化命名；只增不改
P5  条目带路径    —— 每条必须可解析到真实文件
P6  加词先查重    —— 严禁一概念两代号 / 一词两表
P7  失效可校验    —— 每次压缩后跑可达性检查（可机器化）
```

---

## 七、可推广性（不限记忆文件）

同一机制适用于**任何"常驻 + 有硬上限"的文本**：

- Agent 启动文件（MEMORY / USER / AGENTS / SOUL 类）
- 项目规范总索引（本项目 `00_总索引.md` 已用同法）
- 长 CHANGELOG / 决策记录（ADR）的常驻摘要
- 提交信息模板 / 团队术语表

**判据**：`是否每轮都要注入？` + `是否反复出现长概念？` → 两条都"是"就适用。
