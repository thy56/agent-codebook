# 04 · 三级概括法规范

> **本文是本项目的核心规范。** 定义一套**跨域统一**的三级压缩模型：
> 同一个阶梯，套用到 **文本 / 代码 / 日志数据** 三个域。
>
> 与既有文档的关系：
> - `01_设计思路.md` —— 讲**字典外置**（本规范 **L3 的实现机制**）
> - `02_调研报告.md` —— 讲**场景与对照**（本规范 **§六 为何有必要**）
> - `03_失效模式.md` —— 讲**故障与防复发**（本规范 **§五 门禁** 的来源）
> - **本文** —— 讲**三级阶梯本身**（上位框架）

---

## 一、统一模型

### 1.1 一个阶梯，三个域

```
                  L1 完整形态   ──归约──▶   L2 精简形态   ──编码──▶   L3 代号形态
                  ────────────────────────────────────────────────────────────────
文本 / 段落        完整句                精简句（去修饰·抽关键）      关键词代号
代码              完整实现               功能封装（签名·职责）        结构代号
日志 / 大数据      原始行                 模板行（挖模板·抽字段）      模板代号 + 统计
```

**三域共用同一结构**，差别只在**"归约"与"编码"的具体规则**（§三）。

### 1.2 三级各司其职（**关键** —— 不是"越压越好"）

| 级 | 位置 | 用途 | 额度成本 | 读取时机 |
|:--|:---|:---|:---|:---|
| **L3** | **常驻**（每轮注入） | 让模型**知道有什么** | 🔴 最贵 | 每轮 |
| **L2** | **索引**（按需读） | 让模型**快速判断相关性** | 🟡 中 | 命中时 |
| **L1** | **存档**（按需读） | 让模型**拿到真相** | 🟢 不占常驻 | 取证时 |

> ⚠️ **本规范第一条铁律**：
> **三级不是"压缩率的三个档次"，而是"三种用途的三个位置"。**
> 把 L1 原文塞进常驻注入，或用 L3 代号做最终取证 —— **都是误用。**

### 1.3 为什么这个阶梯能治"截断安全"（承 `03_失效模式.md`）

**内嵌字典的老故障**：字典排文末 → 尾部截断先切字典 → 代号全变天书。

**三级法的解法**：

```
常驻（L3）只放【极短代号序列】+【词表索引】  → 被截断的损失极小（且可设计为前缀优先）
索引（L2）独立成文件                        → 不受常驻截断影响
存档（L1）原文不动                          → 永远可取证
```

> **即：把"单文件里塞三层"改成"三层各占一个文件"。**
> 这是 `01` 篇"字典外置"的**推广** —— 从"字典外置"推广到"每级外置"。

## 二、等级定义与判据（可机器校验）

### 2.1 通用判据（三域共用）

| 级 | 必须满足 | 必须**不**满足 |
|:--|:---|:---|
| **L1** | 与来源**逐字一致**（可 diff 验证） | — |
| **L2** | ① 保留全部**信息要素**（数值/路径/命令/结论/因果/条件）② 每个 L2 单位可**指回** L1 位置 | 不含纯修辞、套话、重复 |
| **L3** | ① 每个代号在字典中**有唯一定义** ② 字典条目**可解析到真实路径** ③ 代号序列长度 ≤ L2 的 1/3 | 不含未登记代号 |

### 2.2 域 A · 文本

| 级 | 定义 | 操作 |
|:--|:---|:---|
| **L1** 完整句 | 原文段落 | — |
| **L2** 精简句 | 只留"带信息的成分" | ① **删套话** ② **删程度修饰** ③ **去重** ④ **抽关键句** |
| **L3** 关键词码 | 关键词 → 代号 | 只对「**高频 × 长**」的概念编码 |

**L2 的四步细则**：

| 步 | 规则 | 例 |
|:--|:---|:---|
| ① 删套话 | 删「值得注意的是/需要指出的是/综上所述」等**框架词**，**保留其后的结论** | 「综上所述，A 成立」→「A 成立」 |
| ② 删程度修饰 | 删**不改变真值**的程度副词（非常/十分/极其/格外） | 「非常重要的是」→「重要的是」 |
| ③ 去重 | 同义反复取一 | 「首先要先」→「先」 |
| ④ 抽关键句 | **必留**：含数值/日期/路径/命令/结论/因果/条件/转折 的句子<br>**可降级**：纯铺垫、举例、修辞 | — |

> ⚠️ **② 有例外**：当程度词**本身承载信息**时不得删。
> 例：「**仅**支持 3 种格式」的「仅」表限界，**删了就变事实错误** → 归入 §三 必留词。

**L3 编码门槛**（沿用 `01` 篇）：
```
编码收益 = (原表达字符数 − 代号字符数) × 出现次数 − 字典登记成本
编码收益 > 0 才编；否则不编
```

### 2.3 域 B · 代码

**注意本域方向与文本相反** —— 代码的"完整含义"是**结构**，展开才是实现：

| 级 | 定义 | 内容 | 类比 |
|:--|:---|:---|:---|
| **L1** 片段级 | 完整实现 | 函数体全文 | 原文 |
| **L2** 功能级 | 功能封装 | 签名 + docstring 首行 + 关键分支/常量 | 精简句 |
| **L3** 结构级 | 结构封装 | 模块 → 类 → 函数**清单** + 职责一行 | 关键词码 |

**L2/L3 的硬要求**：

| 项 | 要求 |
|:---|:---|
| **签名** | 必须**完整保留**（含默认值、类型标注）—— 签名是接口契约 |
| **docstring** | 保留**首行**（职责句）；详细参数可降级 |
| **关键行** | 保留：**常量定义、异常抛出、鉴权/校验、外部调用、返回** |
| **丢弃** | 局部变量赋值、循环体细节、日志打印、注释掉的死代码 |
| **行号锚点** | L2/L3 每项**必须带 L1 行号**，保证可回查 |

**L3 代号格式**（按功能语义）：
```
F-<域>-<动作>       如 F-AUTH-VERIFY / F-DB-CONNECT
C-<域>-<职责>       如 C-EXAM-SCORER（类）
M-<域>              如 M-EXAM-HUB（模块）
```

### 2.4 域 C · 日志 / 大数据

**本域是唯一可做到 100% 无损的**（模板 + 字段可完全重建）：

| 级 | 定义 | 内容 |
|:--|:---|:---|
| **L1** 原始行 | 全量日志 | 逐行原文 |
| **L2** 模板行 | 挖模板，变量位抽成字段 | `ERROR {svc} code={n}: {msg}` + 字段表 |
| **L3** 模板码 | 模板 → 代号 + 计数 | `L-E01 ×137` |

**模板化规则**：
```
1. 按 token 切分（空白/常见分隔符）
2. 变量位识别 → 替换为 <*>
   数字 / UUID / 时间戳 / 路径 / IP / 十六进制 / 引号内容
3. 签名相同（token 数 + 常量 token 相同）→ 归为同一模板
4. 模板按出现次数降序编号 L-<类型><序号>
```

**无损契约**（L2 必须满足）：
```
∀ 行 i：render(template_i, fields_i) == line_i     ← 必须逐字相等
```
> 不满足 → **该行不得模板化**（保留为 L1），并计入报告。

## 三、⭐ 无损契约与损失标记（**本规范最关键部分**）

### 3.1 问题

**L1→L2 的"归约"本质是有损的** —— 删掉的修饰词不会自己回来。
如果不标记，使用者分不清"这是压缩结果"还是"这是原文" → **复现静默失效**。

### 3.2 三级损失标记

**每个 L2/L3 单位必须带一个标记**：

| 标记 | 名称 | 含义 | 可用性 |
|:--|:---|:---|:---|
| `≡` | 严格等价 | 与原文字面/语义**完全一致**（如纯去重、日志模板化） | 🟢 可当原文用 |
| `≈` | 语义等价 | 信息**要素**全保留，措辞/结构有变（如去套话、代码封装） | 🟢 可作依据 |
| `⊃` | **信息损失** | 丢失了**某类信息** → **必须注明丢了什么** | 🔴 **不可作最终依据** |

**`⊃` 必须带损失类别标签**：

| 标签 | 丢了什么 | 典型场景 |
|:--|:---|:---|
| `⊃修饰` | 程度/语气/情感色彩 | 删了「非常」「极其」 |
| `⊃举例` | 说明性例子 | 删了「例如…」 |
| `⊃推导` | 中间推理步骤 | 只留结论 |
| `⊃细节` | 实现/参数细节 | 代码只留签名 |
| `⊃样式` | 格式/排版 | — |

### 3.3 使用规则（**铁律**）

```
✅ L3/L2 带 ≡ 或 ≈  → 可直接用于判断/决策/引用
⚠️ L3/L2 带 ⊃       → 只能用于【定位】，【不得】作为最终依据
🔴 任何最终结论/取证  → 必须回到 L1
```

> **这就是"三级"存在的意义**：不是省字符，而是**让"我读到的是哪一级"变得明确**。
> 老故障的可怕之处正是"**不知道自己读的是压缩结果**"。

## 四、编码规则（L3 通用）

### 4.1 代号格式

| 域 | 前缀 | 示例 |
|:---|:---|:---|
| 通用概念 | 无 / `W-` | `RL-3`、`GUARD-2` |
| 文本关键词 | `T-` | `T-INJECT-LIMIT` |
| 代码功能 | `F-` / `C-` / `M-` | `F-DB-CONNECT` |
| 日志模板 | `L-` | `L-E01` |

**约束**：
```
① 只用 [A-Z0-9-]（全大写 + 连字符）—— 避免与正文普通词撞车
② 长度 ≤ 24 字符
③ 只增不改（历史正文可读性）
④ 全局唯一（跨文件、跨会话）
```

### 4.2 字典必备列

```
| 代号 | 含义 | 级别 | 详情位置（可解析真实路径） |
```

- **含义**：一句话（供模型直接理解）
- **级别**：该代号代表什么级别的信息（`≡`/`≈`/`⊃`）—— **让使用者知道能信到什么程度**
- **详情位置**：必须**真实存在** → 用 `tools/lexicon_check.py` 机器校验

### 4.3 加词流程（防一词两表）

```
1. 查重：新概念是否已有代号？（大小写不敏感）
2. 查门槛：编码收益 > 0 ？（§2.2 L3 编码门槛）
3. 定级：≡ / ≈ / ⊃（含损失标签）
4. 登记：代号｜含义｜级别｜真实路径
5. 校验：跑 lexicon_check.py，FAIL 必须为 0
```

## 五、质量门禁（可机器校验）

### 5.1 逐级门禁

| 级 | 门禁 | 校验方式 |
|:--|:---|:---|
| **L1** | 与来源一致 | `diff` / 哈希对比 |
| **L2（文本）** | 信息要素零丢失 | 必备要素清单（数值/路径/命令/结论）逐项 grep |
| **L2（代码）** | 签名完整 + 行号锚点存在 | AST 比对签名；行号回查 |
| **L2（日志）** | 可重建 | `render(template, fields) == line` |
| **L3（全域）** | 代号有定义 + 路径可达 + 无孤儿 | `lexicon_check.py` |

### 5.2 越级使用检查（防误用）

```
□ 常驻注入里是否混入了 L1 原文？            → 违规（浪费额度）
□ 是否用带 ⊃ 的 L2/L3 下了最终结论？        → 违规（依据不足）
□ L3 代号是否在【无字典】的场合出现？        → 违规（变天书）
□ 字典是否与被压缩内容【在同一文件】？      → 违规（回到老故障）
```

### 5.3 报告必备字段

每次压缩必须产出报告，含：
```
输入字符数 / L1·L2·L3 各级字符数 / 压缩比
各级损失标记分布（≡ / ≈ / ⊃ 各多少）
未压缩项（无法归约或模板化的）及原因
门禁结果（OK / FAIL / WARN）
```

## 六、为何有必要（承 `02_调研报告.md`）

| 证据 | 数值 |
|:---|:---|
| 本仓常驻注入硬上限 | 单文件 **20,000 字符**，超限**静默尾部截断** |
| Claude Code | `MEMORY.md` **前 200 行 / 25 KB** |
| Hermes Agent | `MEMORY.md` **2,200 字符**，写入报错 |

**结论**：三级法把"**一个文件装不下**"变成"**三层各装一部分**" —— 这是对硬约束的直接应答。

## 七、反例库（**至少记 2 个真实反例**）

### 反例 1 · 把 L1 塞进常驻（额度爆炸）

```
❌ 做法：把 20KB 的日志原文放进常驻注入
后果：撞上限 → 静默截断 → 后半段丢失且无标记
正确：L3 模板码常驻（约 200 字符）+ L1 存文件
```

### 反例 2 · 用 ⊃ 级信息下结论（依据不足）

```
❌ 做法：代码只留签名（⊃细节），据此判断"错误处理完整"
后果：错误处理恰在被丢弃的实现细节里 → 结论错
正确：标 ⊃细节，结论前回读 L1
```

### 反例 3 · 去修饰词删掉了限界词（事实改变）

```
❌ 原文：「仅支持 3 种格式」，删「仅」→「支持 3 种格式」
后果：语义从"排他"变"至少"，是**事实错误**而非"精简"
正确：「仅」属必留词（表限界），不得删
```

### 反例 4 · 模板化破坏了可重建性

```
❌ 做法：把 `code=200` 和 `code=500` 归为同一模板，字段位丢失
后果：无法重建原行 → L2 门禁 FAIL 却被忽略
正确：模板签名必须含【全部常量 token】；重建失败的行不模板化
```

## 九、已知限制（诚实声明）

| # | 限制 | 说明 |
|:--|:---|:---|
| 1 | **文本 L2 是启发式** | 去修饰/抽关键句靠词表 + 规则；**达不到人工精修水平**；词表可扩展 |
| 2 | **代码域仅 Python 用 AST** | 其他语言走正则大纲（**降级**，已标注） |
| 3 | **日志模板化非最优** | 简化的签名聚类（非 Drain 全量算法）；长模板/多行日志支持有限 |
| 4 | **收益随内容而异** | 已精简的文本收益低（与 `02` 篇引述的 2~7% 一致） |
| 5 | **跨语料基准规模有限** | 已提供 `tools/benchmark.py`（多文件逐项比值 + 往返完整性）；语料仍以本仓为主 |
| 6 | **未接 CI** | 门禁需手工跑 |
