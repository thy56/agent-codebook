# 05 · 引索符系统设计（提案）

> **本文是 `agent-codebook` 开源项目的核心设计稿。**
> 上一版（三级概括法）定义了"怎么归约"；本文定义"**归约之后用什么符号表达**"。
>
> 状态：**提案 · 待老大审定**（未定稿，未实现）

---

## 一、项目定位

```
agent-codebook
把长内容改写成「代号 + 引索符」，代号指向外置字典库。
压缩后的内容只保留符号串 —— 可解析、可校验、可组合。
```

**四要素**（老大原始构想）：

| # | 要素 | 作用 |
|:--|:---|:---|
| 1 | **关键词抽取** | 从原文找出"长 × 高频"的语义单元 |
| 2 | **代号编码** | 英文/字母数字形式的语义化短代号 |
| 3 | **引索符组织** | 用**固定符号集**把代号组织成结构化表示 |
| 4 | **字典外置** | 代号 → 含义 + 详情路径，**不占常驻额度** |

---

## 二、与现有项目的差异（诚实版）

调研过 GitHub 与生态后的结论。**它们做"删减 + 替换"，我们做"重构为符号表示"**：

| 项目 | 它做什么 | **它不做什么** |
|:---|:---|:---|
| `claw-compactor`（PyPI, 1600+ 测试） | 14 阶段**删减** + `$XX` 纯编号替换 | ❌ 纯编号**无语义、无语法**；不重构表示法 |
| `context-compress` | 压成 pipe-delimited 索引行 | ❌ 只是"索引行"，不是一套符号系统 |
| `openclaw-memory-compact` | 拆 `memory/details/` + 保留索引 | ❌ 无代号编码、无引索符 |
| `LLMLingua` 系（6.6k⭐） | token 级**剪枝**（有损） | ❌ 不换表示法，只是删 |
| `mcp-compressor`（Atlassian） | 工具描述渐进披露 | ⚠️ 不同轴（工具面，非记忆内容） |

**差异的实质**：

> **它们是"把原文压短"；我们是"把原文改写成结构化符号"。**

换表示法带来压缩之外的能力：

| 能力 | 说明 | 纯删减能否做到 |
|:---|:---|:---|
| **可解析** | 有确定语法 → 机器解析成树，不用猜 | ❌ |
| **可校验** | 格式固定 → 能机器检缺字段/坏引用 | ⚠️ 部分 |
| **可组合** | 代号能嵌套表达关系 | ❌ |
| **可定位** | 按路径直达，不用全文搜 | ❌ |

> ⚠️ **不主张**："我们发明了字典压缩" —— 缩写字典、无损可逆、多保真度均有先例
> （`CompactPrompt`、arXiv:2604.13066、`claw-compactor` RewindStore、arXiv:2607.08032 的 `P-fid`）。
> **我们主张的是这个组合**：代号编码 + 引索符语法 + 外置字典 + 可校验。

## 三、⭐ 引索符系统（本文核心）

### 3.1 设计原则

| # | 原则 | 理由 |
|:--|:---|:---|
| 1 | **纯 ASCII** | 跨系统/跨编码安全（我们踩过 GBK 乱码的坑） |
| 2 | **少而够用** | 符号越多越难学；目标 **≤ 18 个** |
| 3 | **可组合** | 小符号集拼出复杂语义，而非给每种情况造新符 |
| 4 | **与自然文本可区分** | 代号全大写+连字符；符号不与常见标点混淆 |
| 5 | **自解释头部** | 顶部一行声明"本文用到哪些符 + 字典指针"，**极短** |
| 6 | **模态必留** | 承接"保护词"教训（删「仅」= 事实错误） |

### 3.2 符号集（草案 · 5 类 18 符）

#### A 类 · 结构符（分隔 / 组织）

| 符号 | 名称 | 含义 | 例 |
|:--|:---|:---|:---|
| `\|` | 并列分隔 | 同级项 | `RL-3\|GUARD-2` |
| `:` | 键值绑定 | 字段:值 | `state:active` |
| `>>` | 从属 | 下级/子项 | `EXAM>>scoring` |
| `;;` | 单元终止 | 结束一个语义单元 | `... ;;\|...` |
| `//` | 路径 | 层级路径 | `mem/rules/silent-fail` |

#### B 类 · 引用符（前缀，指向字典）

| 符号 | 名称 | 含义 |
|:--|:---|:---|
| `@` | **解析引用** | 必读字典展开（主要用法） |
| `?` | 待解析 | 未登记/含义待定 → **必须补** |
| `^` | 回引 | 上文已展开，此处复用 |

> **约定**：代号本体为 `[A-Z][A-Z0-9]*(-[A-Z0-9]+)+`（如 `RL-3`）。
> **裸代号在符号串里默认就是引用** —— `@` 用于强调"必须展开"。

#### C 类 · 模态符（前缀，约束语义）⭐ **不可省**

| 符号 | 含义 | 由来 |
|:--|:---|:---|
| `!` | **必须** | 保护词 |
| `-` | **禁止** | 保护词 |
| `+` | 应当 / 建议 | — |
| `~` | 允许但不要求 | — |
| `?` | 待确认 / 未验证 | 我们现有 ⚠️ 标记 |

> ⚠️ **为什么必须有这一类**：我们真实踩过 —— 删掉「**仅**支持 3 种格式」的「仅」，
> 语义从"排他"变"至少"，**是事实错误，不是精简**。
> 纯删减类工具**没有表达模态的位置** → 必然丢掉这类信息。

#### D 类 · 关系符（中缀，连接语义）

| 符号 | 含义 |
|:--|:---|
| `>` | 导致 / 因此 |
| `<` | 因为 / 依赖 |
| `&` | 且 |
| `/` | 或 |
| `=` | 等价 / 即 |

#### E 类 · 保真度后缀（承接三级概括的损失标记）

| 后缀 | 含义 | 可用性 |
|:--|:---|:---|
| `.=` | 严格等价 | 🟢 可当原文用 |
| `.~` | 语义等价 | 🟢 可作依据 |
| `.!` | **有损**（须注明丢了什么） | 🔴 **不可作最终依据** |

### 3.3 自解释头部（关键设计）

**每个压缩单元的顶部一行**，声明版本 + 用到的符号 + 字典位置：

```
#LX1 @dict=mem/lexicon.tsv | mods=!-? | fid=yes
```

| 段 | 含义 | 是否必填 |
|:---|:---|:---|
| `#LX1` | 格式版本（便于将来演进） | ✅ |
| `@dict=<路径>` | 字典位置（**只声明一次**，不逐条写） | ✅ |
| `mods=...` | 本单元用到的模态符（未声明的默认不出现） | 可选 |
| `fid=yes` | 是否有保真度后缀 | 可选 |

**约 50 字符** —— 用极小代价换来"任何 agent 拿到就能定位字典 + 知道该读哪些符"。

### 3.4 完整示例

#### 例 A：**单句** —— ⚠️ 会膨胀（诚实反例）

**L1 原文**（35 字符）：
```
禁止未授权访问：任何情况下都必须校验令牌，且仅允许管理员执行危险操作。
```

**L3 符号串**（54 字符，短代号 `U1`/`V1`/`D1`）：
```
#LX1 @dict=mem/lexicon.tsv | mods=-!
-@U1|!@V1|!@D1.~
;;
```

**结论：35 → 54，膨胀 1.54×。**

> ⚠️ **这不是 bug，是原理**：符号串有固定开销（头部 36 字符）。
> **内容短于约 250 字符时，压缩必为负。**
> 这一条必须写进 README 的诚实声明 —— 小内容**不该用**这套方法。
> （对比：长代号方案下是 77 字符 / 膨胀 2.20× → **短代号确实明显更好**）

#### 例 B：**规则块** —— 真正的适用场景

**L1 原文**（127 字符）：
```
红线1：绝不用 taskkill /F 强杀网关，会跳过 WAL 归并。
红线2：绝不设 ALLOW_MULTI_GATEWAY，多开互抢端口会触发断路器。
红线3：重启用 openclaw gateway restart，别用 stop+start 叠加。
```

**L3 符号串**（52 字符，短代号 `R1`/`R2`/`R3`）：
```
#LX1 @dict=mem/lexicon.tsv | mods=-!
-@R1|-@R2|-@R3
;;
```

**字典**（外置，不占常驻）：
```
#code	term	meaning	fidelity	detail_path
R1	红线1	绝不 taskkill /F 强杀网关（跳过 WAL 归并）	.~	docs/rules/rl.md
R2	红线2	绝不设 ALLOW_MULTI_GATEWAY（多开互抢端口）	.~	docs/rules/rl.md
R3	红线3	重启用 openclaw gateway restart，勿 stop+start 叠加	.~	docs/rules/rl.md
```

**结论（实测字符数）：127 → 52，2.44 : 1（省 59%）。**
去掉 36 字符头部后，**正文只有 16 字符（省 87%）**。

> **对比长代号方案**：正文 22 字符 → 16 字符，**再省 27%**。
>
> **两个例子的对比就是适用边界**：收益来自**重复与结构**（多条规则共享同一表示），
> **不来自单条内容**。

### 3.5 ⚠️ 设计关键：代号的**长度成本**（实测）

**这是一个必须面对的问题**：对**中文**内容，英文语义化代号**比原词更长**。

| 代号 | 原词 | 代号字符 | 原词字符 | 判定 |
|:---|:---|:---|:---|:---|
| `AUTH-UNAUTH` | 未授权访问 | 11 | 5 | ✗ 更长 |
| `SILENT-FAIL` | 静默失效 | 11 | 4 | ✗ 更长 |
| `INJECT-LIMIT` | 注入上限 | 12 | 4 | ✗ 更长 |
| `GUARD-2` | 防护 | 7 | 2 | ✗ 更长 |
| **均值** | | **9.6** | **3.4** | **2.85×** |

**两种口径结论相反**：

| 口径 | 代号 vs 原词 | 含义 |
|:---|:---|:---|
| **字符**（OpenClaw `bootstrapMaxChars` 正是字符口径） | **长 2.85×** | 英文代号**让中文内容变大** |
| **token**（多数 API 计费） | **0.74×**（更省） | 估算值，未装 tokenizer |

**→ 核心结论（与口径无关）**：

> **压缩的真正来源不是「代号比原词短」，而是「把内容搬去外置字典」。**

因此三条硬约束：

| # | 约束 | 理由 |
|:--|:---|:---|
| 1 | **压缩单元必须是整句/整条规则** | 单词替换必亏（例 A 膨胀）；整条替换才赚（例 B 省 83%） |
| 2 | **代号越短越好** | 指针比内容还长，就白搬了 |
| 3 | **代码风格要按场景选** | 见下表 |

**代号风格 —— ✅ 已定：紧凑短代号（2~4 字符）**

| 方案 | 例 | 字符成本 | 可读性 | 结论 |
|:---|:---|:---|:---|:---|
| 语义化英文 | `SILENT-FAIL` | 11（2.85×） | 人可读 | ❌ 字符口径亏 |
| **紧凑短码** | `R1` `S1` `U1` | **2~4** | ❌ 交给字典 | ✅ **已采用** |
| 中文简称 | `静失` | 2 | 可猜 | ❌ 非 ASCII（踩过 GBK 坑） |

**实测效果（例 B）**：127 → 52 字符（2.44 : 1，省 59%）；
正文部分 **22 → 16 字符，再省 27%**。

### 3.6 ⚠️ 短代号的三个连带设计（必须同步做，否则会坏）

#### 连带 1：**必须用引用符界定，不能裸用**

短代号极易与正文撞车。实测 4/4 场景都会误识别：

| 场景 | 正文 | 裸代号会误识别？ |
|:---|:---|:---|
| `R1` 在普通文本里 | `see R1 of the spec` | ⚠️ 会 |
| `S1` 是相机型号 | `camera S1 released` | ⚠️ 会 |
| `A1` 是纸张规格 | `paper size A1 is 594x841` | ⚠️ 会 |
| `F2` 是按键名 | `press F2 to continue` | ⚠️ 会 |

**→ 铁律：符号串里代号一律带引用符（`@R1`）**

| 写法 | 结果 |
|:---|:---|
| `R1`（裸） | ❌ 与正文歧义，无法区分 |
| `@R1` | ✅ 明确“这是引用，去字典查” |

> **额外好处**：正文里出现的 `R1` 不会被误当引用 —— **歧义是双向的，界定后两边都安全。**

#### 连带 2：**必用命名空间，否则 2~4 字符空间很快撞车**

**方案 A · 类别前缀 + 序号（已采用）**

| 前缀 | 类别 | 例 |
|:---|:---|:---|
| `R` | 规则（Rule） | `R1` `R2` |
| `S` | 状态（State） | `S1` |
| `F` | 功能（Function） | `F1` |
| `D` | 数据 / 字典项（Data） | `D1` |
| `M` | 模块（Module） | `M1` |

**方案 B**（备选）：全局纯序号 `C1..Cn` —— 最短，但完全不可猜。

> ⚠️ **若用方案 A，类别字母必须在自解释头部声明**，否则新 agent 不知道 `R` 是什么。
> 头部成本会增加几个字符 —— 这是“短代号”换来的必要代价。

#### 连带 3：**字典必须新增「原名」列**

短代号不可读 → **字典不加原名，人就审不了**：

```
#code	term	meaning	fidelity	detail_path
R1	红线1	绝不 taskkill /F 强杀网关（跳过 WAL 归并）	.~	docs/rules/rl.md
R2	红线2	绝不设 ALLOW_MULTI_GATEWAY（多开互抢端口）	.~	docs/rules/rl.md
R3	红线3	重启用 openclaw gateway restart，勿 stop+start	.~	docs/rules/rl.md
```

| 列 | 必填 | 说明 |
|:---|:---|:---|
| `code` | ✅ | 2~4 字符，全局唯一，**只增不改** |
| `term` | ✅ | ⭐ **原名**（短代号不可读，此列是人类审阅与回查的唯一入口） |
| `meaning` | ✅ | 一句话（多数场景读到这层就够） |
| `fidelity` | ✅ | `.=` / `.~` / `.!` |
| `detail_path` | ✅ | **可解析真实路径**（机器可校验） |
| `match` | 可选 | 源文本匹配串（供 encoder 自动替换） |

> **没有 `term` 列的后果**：字典变成 `R1=?` 的天书，人无法审阅 →
> **直接违反本项目“可校验”的主张。**

## 四、项目结构（开源项目标准形态）

```
agent-codebook/
├── README.md              门面：是什么 / 解决什么 / 怎么用 / 状态
├── SKILL.md               ⭐ agent 入口（Claude Code / OpenClaw / Cursor 都认）
├── LICENSE                MIT
├── CHANGELOG.md
├── docs/
│   ├── 00_快速上手         5 分钟跑通
│   ├── 01_引索符系统.md    ⭐ 本文（符号表 · 语法 · 示例）
│   ├── 02_代号命名规范.md
│   ├── 03_字典库规范.md
│   ├── 04_三级概括法.md    文本 / 代码 / 日志
│   ├── 05_保真度与损失.md
│   └── 06_负例库.md        ⭐ "这样是错的"
├── src/
│   ├── encode.py           原文 → 符号串
│   ├── decode.py           符号串 → 原文（回读）
│   ├── validate.py         一致性校验（代号有定义/路径可达/引索符合法）
│   └── lexicon.py          字典读写
├── tests/
│   ├── vectors/            ⭐ 黄金向量（输入 → 期望输出）
│   └── run_tests.py        跑通 = 实现正确
└── examples/
    ├── memory_rules.lx     真实示例（我们的 MEMORY.md）
    └── lexicon.tsv         对应字典
```

### 为什么必须有 `tests/vectors/`（黄金向量）

**这是把"能用"变成"可验证"的唯一手段**：

```
任何 agent / 任何人改完实现 → 跑一遍向量
  全过 → 实现正确
  没过 → 知道自己错了（而不是"看起来对"）
```

> 这一条直接对应我们 M-05 的教训：**"看起来对" ≠ "真的对"**。

## 五、⚠️ 诚实声明（必须写进 README）

| # | 限制 | 说明 |
|:--|:---|:---|
| 1 | **短内容会膨胀** | 符号串有固定开销（头部 ~50 字符）；**内容短于约 300 字符时，压缩可能为负** —— 实测过（日志域小样本 L2 > L1 达 161%） |
| 2 | **收益随内容而异** | 已精简的文件收益低（2~7%，与文献一致） |
| 3 | **抽取质量有天花板** | 纯规则抽取弱于人工；LLM 抽取要花 token 且结果不确定 |
| 4 | **需学一次** | 使用者（人/agent）要先读规范；**但读一次后可长期复用** |
| 5 | **无大规模基准** | 目前数据来自我们自己的实测，**未做跨语料基准** |
| 6 | **非首创** | 见 §二；我们主张的是**组合与可校验性** |

## 六、建议的最小可学版本（MVP）

**先做最小闭环，验证"能不能学会、学会有没有用"**，再扩：

| 阶段 | 产出 | 验收 |
|:---|:---|:---|
| **M0** | 规范骨架（符号表 + 语法 + 字典格式 + 负例 3 条） | 老大审定符号表 |
| **M1** | `src/` 三角（encode / decode / validate） | 自身往返通过 |
| **M2** | 黄金向量 + 2 个真实示例 | 向量全过 |
| **M3** | `README` + `SKILL.md` 公开版 + LICENSE | — |
| **M4** | 发布 GitHub | ⚠️ **需老大明确授权（git 是红线）** |

**建议先做 M0~M2** —— 因为"**这套符号能不能学会、学了对不对**"这个假设，越早验证越好；做全了再发现学不会就白费。
