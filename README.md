# 字典压缩法 · Dictionary Compression for Agent Memory

![tests](https://img.shields.io/badge/tests-43%2F43%20passing-brightgreen)
![dependencies](https://img.shields.io/badge/dependencies-zero-brightgreen)
![python](https://img.shields.io/badge/python-3.9%2B-blue)
![license](https://img.shields.io/badge/license-MIT-green)

> 给 AI Agent 的**常驻记忆**做可校验的压缩：**索引留在正文，字典移到文件外。**
>
> 把反复出现的长概念换成**稳定短代号**（如 `SILENT-FAIL`），
> 而**代号表不放在被压缩的正文里**，放在外部按需加载 ——
> 正文只留词名索引，**再也不会因为「从尾部截断」而变成天书**。

---

## 亮点

| 亮点 | 说明 |
|:---|:---|
| **索引在内 / 字典在外** | ← **核心创新**：内嵌字典与正文是**零和**（字典越大，正文越少）；外置后字典**不占常驻额度**，只在展开时读一次 |
| **截断安全** | 字典内嵌且排在文末时，一次尾部截断就让**全部代号变天书**；外置后**无论怎么截断，索引都在、字典都完整** |
| **可逆无损** | 同一概念永远同一代号，映射有据可查 —— 不是有损摘要 |
| **机器可校验** | 形式化规范（20 符符号表 · EBNF · 12 错误码 + 5 警告码 · 13 条校验规则）+ 零依赖参考实现 + **43 项测试**，判据可自动执行 |
| **零依赖** | 实现与工具链只用 Python 标准库 |

## 快速上手

**它是什么**：AI Agent 的常驻上下文（`MEMORY` / `AGENTS` / `USER` 这类注入文件）有硬性字符上限，
且**超限从尾部静默截断**。本方案把其中的长概念换成稳定短代号，
把「代号 → 含义」的字典**移到文件外**（不占常驻额度），正文只保留一行词名索引。

**跑起来**（零第三方依赖，仅需 Python 3.9+）：

```bash
git clone https://github.com/thy56/agent-codebook
cd agent-codebook
python tests/run_tests.py        # 43/43 通过，退出码 0
```

**最小示例**（详见规范 §16）：

```text
输入（三条规则，118 字符）
  红线1：不可逆操作必须走优雅停止流程，禁止使用强制终止进程的方式跳过收尾清点步骤。
  红线2：禁止同时运行多个实例进程，否则端口冲突会触发系统的保护性自动停用机制。
  红线3：重启必须使用统一的命令入口，禁止以先停后起叠加的两次独立操作来替代。

符号串（45 字符，常驻）
  #LX1 dict=lexicon.tsv mods=-!
  -@R1|-@R2|-@R3
  ;;

字典（外置，不常驻）
  code  term    meaning                              fidelity  detail_path
  R1    红线1    不可逆操作必须走优雅停止流程，禁止强制终止  .~        docs/rules.md
  R2    红线2    禁止同时运行多个实例，端口冲突会触发保护性停用  .~        docs/rules.md
  R3    红线3    重启必须使用统一的命令入口，禁止先停后起叠加  .~        docs/rules.md
```

正文只剩 45 字符 + 一个指针；含义在**需要展开时**读字典。
详细格式、符号表（20 符）、错误码（12 + 5）见 [`docs/05_引索符系统规范.md`](docs/05_引索符系统规范.md)。

## 它解决什么问题

| # | 约束 | 表现 |
|:--|:---|:---|
| 1 | **注入有硬上限** | 启动文件单文件上限 20,000 字符、合计 60,000；**超限静默截断** |
| 2 | **超限从尾部截断** | 被切掉的是**文末内容**，不是"最不重要的内容" |
| 3 | **长概念反复占 token** | 同一套规则 / 项目 / 术语在多个条目里重复展开 |

**推论**：任何把解释性内容留在正文里的压缩方案，最终都会**挤压正文**或**被截断毁掉**。

## 它带来什么

| 能力 | 说明 |
|:---|:---|
| **省常驻额度** | 示例中常驻内容 118 → 45 字符（**省 62%**）；token 估算省 69%~84%（未装 tokenizer，为估算区间）。注意口径：省的是**常驻额度**，计入外置字典后总量会增加 |
| **本地概念索引库** | 沉淀 `代号 → 含义 / 取证位置 / 保真度` 的索引；`INV-2`（代号只增不改）保证索引**只增长、不腐烂**。它存的是**索引**，内容本体仍在原文件 |
| **载体分离** | 字典与正文分离存放 → **持字典方可还原**。与「把内容删短」有本质差别：删短**不可逆**，外置索引**可逆** |
| **少读常驻** | 每轮只需常驻一小段索引，不必常驻全部定义；纯 ASCII 的符号串也**规避了 GBK / BOM 编码问题** |
| **正文更简洁** | 上例中去掉头部后，正文仅 14 字符 |

> **边界**：本方案提供的是**载体分离（需字典方可还原）**，属**访问门控**（字典即钥匙），
> **不是**加密 —— 无密钥、无算法、不提供完整性保护，且条目数 / 模态 / 结构仍可被观察。
> 三条前提与「禁止宣称」清单见规范 [`§2.3`](docs/05_引索符系统规范.md)。

## 工作原理

### 三级概括法（骨架）

同一架阶梯套用到三个域 —— **越往上越省额度，也越需要回读原文**：

| 域 | L1 完整 | → | L2 精简 | → | L3 代号 |
|:---|:---|:---|:---|:---|:---|
| **文本** | 完整句 | 归约 | 精简句（去套话·抽关键） | 编码 | 关键词代号 |
| **代码** | 完整实现 | 封装 | 功能（签名·职责） | 编码 | 结构代号 |
| **日志** | 原始行 | 挖模板 | 模板行 + 字段 | 编码 | 模板码 + 计数 |

| 级 | 位置 | 用途 | 额度成本 |
|:--|:---|:---|:---|
| **L3** | **常驻**（每轮注入） | 让模型知道**有什么** | 🔴 最贵 |
| **L2** | **索引**（按需读） | 让模型判断**相关性** | 🟡 中 |
| **L1** | **存档**（按需读） | 让模型拿到**真相** | 🟢 不占常驻 |

**损失标记**（每个 L2/L3 单位必带）：`≡` 严格等价 · `≈` 语义等价 ·
`⊃修饰` / `⊃细节` / `⊃举例` / `⊃推导` = **有损，须注明丢了什么，且不可作最终依据**。
完整规范见 [`docs/04_三级概括法规范.md`](docs/04_三级概括法规范.md)。

### 三步机制（L3 的实现）

1. **稳定代号替换**（可逆、无损）—— 同一概念永远同一代号，跨会话 / 跨文件不变
2. **索引在内 / 字典在外** ← 核心 —— 内嵌字典与正文是**零和**（字典越大正文越少）；
   外置后字典**不占常驻额度**，只在需要展开时读一次
3. **截断安全** —— 字典内嵌且排在文末时，一次尾部截断就会让**全部代号变天书**；
   字典外置后，**无论怎么截断，索引都在、字典都完整**

## 适用场景

**强适用**
- ✅ Agent 启动注入文件（system prompt 常驻段、`MEMORY` / `USER` / `AGENTS` 类文件）
- ✅ 有硬性字符上限、且**超限静默截断**的记忆文件
- ✅ 概念高频复现的长期项目（术语表、规则集、踩坑库）

**弱适用 / 不适用**
- ❌ 一次性内容（没有重复，无收益）
- ❌ 纯自然散文（代号会破坏可读性）
- ❌ 已经贴近上限且**不能再拆**的极短文件

## 风险与验证

每项风险都有**可执行**的机器判据 —— 下表第三列即验证命令，照抄即可复现。

| # | 风险 | 已实现的机制 | 验证方式 |
|:--|:---|:---|:---|
| R1 | **字典膨胀**（词太多 → 索引行变长，收益递减） | 索引行长度上限（`--index-budget`，默认 300）；超限时按 term 长度降序列出「应并入字典文件的候选」 | `python tools/lexicon_audit.py <字典.tsv> --index <正文文件> --index-budget 300` → 判据行 `R1 index_budget` |
| R2 | **代号不可读**（外人 / 新会话看不懂代号） | 每条 entry 的 `term` 必须非空（§5.2）；索引行必须是**词名**，出现裸 `@`/`^` 代号即拒（FAIL）；`term` 过短或无可读字母则 WARN | `python tools/lexicon_audit.py <字典.tsv> --index <正文文件>` → 判据行 `R2 term_readable` |
| R3 | **映射漂移**（同一概念两个代号，违 `INV-2`） | 同 `term` 被两个 `code` 使用 → FAIL；同一 `code` 的 `rev` 变化（调 `src/lexicon.compare_rev`）→ FAIL；两条 entry 的 `match` 别名有交集 → WARN | `python tools/lexicon_audit.py <字典.tsv>` → 判据行 `R3 mapping_drift` |
| R4 | **替换收益不确定**（低频概念替换反而多一次跳转） | 对每个 `code` 统计语料出现次数 `freq`，算 `saving = freq × (len(meaning) − len(code))`；`saving ≤ 0` → WARN 并点名该代号；末尾输出总节省字符 | `python tools/lexicon_audit.py <字典.tsv> --corpus <语料文件或目录>` → 判据行 `R4 saving` |
| R5 | **压缩悖论**（激进压缩可能因输出膨胀而**总成本上升**） | 算 `常驻成本`（索引行长度）+ `一次性展开成本`（字典文本长度 × 1），与**基线**（语料原文长度）比；`总成本 > 基线` → FAIL，并把三个数字都打出来（§10.3 盈亏平衡） | `python tools/lexicon_audit.py <字典.tsv> --index <正文文件> --corpus <语料>` → 判据行 `R5 breakeven` |
| R6 | **语义风险**（代号与原意被误联想） | 代号去分隔符后的字母序列须**等于** term 各词首字母（缩写）**或**与 term 有 **≥2 个连续字母**重合；不满足 → WARN 并列出不透明代号；顺序编号默认 WARN，`--allow-seq` 可跳过 | `python tools/lexicon_audit.py <字典.tsv>` → 判据行 `R6 mnemonic`（`--allow-seq` 对照） |
| R7 | **只有单点实测**（一个文件、一份字典不足以支撑结论） | 多文件基准：逐文件算基线 / 压缩后常驻 / 比值，并用 `src/decode.expand_file` **真跑展开**证明可逆，最后给聚合统计与整体比 | `python tools/benchmark.py docs --dict examples/docs_corpus.lexicon.tsv` |

**一键复核**（按上面命令逐条跑；任一项 FAIL 即退出码 1，可直接进 CI 门禁）：

```bash
python tools/lexicon_audit.py --self-test      # 16 组样例自证 R1~R6 各自可触发
python tests/run_tests.py                      # 43/43 通过，退出码 0
```

> **维护铁律**：代号**只增不改**；每条字典项**必须给可解析的真实路径**；每次压缩后**跑一次可达性校验**（`tools/lexicon_check.py`）与**一次审计**（`tools/lexicon_audit.py`）。
